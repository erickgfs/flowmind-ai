O problema e a ideia

O problema

Arrastar à mão é difícil e excludente

  • Mouse e toque, cópia que segue o ponteiro, descobrir a coluna de destino.
  • Quem não usa mouse não consegue arrastar nada.
  • O leitor de tela não diz o que está acontecendo.

O dnd-kit dá as peças: contexto, arrastáveis, áreas de soltar, sensores (inclusive teclado) e anúncios.

Analogia

O aeroporto

  • DndContext = torre de controle.
  • Cartão = avião; coluna = pista.
  • Sensores = manche, toque e piloto automático (teclado).
  • Colisão = radar; DragOverlay = sombra do avião; anúncios = rádio.

Onde falha: a torre só avisa onde o avião pousou (onDragEnd); quem muda os dados e chama a API é o nosso código.

O código, comentado

// o id da coluna É o status
const { setNodeRef, isOver } = useDroppable({ id: status });

<section className={isOver
  ? "border-accent bg-accent-soft"  // destaque
  : "bg-subtle"}>
task-card.tsx · aviãoTSX
const { attributes, listeners, setNodeRef, isDragging } =
  useDraggable({ id: task.id });

<div ref={setNodeRef} {...attributes} {...listeners}
  className={isDragging ? "opacity-40" : ""}>
// attributes: role="button", tabIndex, aria-*
// listeners: ponteiro e teclado
task-board.tsx · sensoresTSX
useSensors(
  useSensor(PointerSensor, {
    activationConstraint: { distance: 4 }, // clique ≠ arrastar
  }),
  useSensor(KeyboardSensor, {
    keyboardCodes: { start: ["Space"],
      cancel: ["Escape"], end: ["Space"] },
    coordinateGetter: jumpBetweenColumns,
  }),
);
task-board.tsx · colisãoTSX
// mouse: coluna sob o PONTEIRO
// teclado (sem ponteiro): maior sobreposição
const columnUnderPointer: CollisionDetection =
  (args) => {
    const hits = pointerWithin(args);
    return hits.length ? hits : rectIntersection(args);
  };

Glossário

DndContext
Coordena o arrastar e dispara os eventos.
useDraggable / useDroppable
Marca o que arrasta / onde se solta.
active / over
O item arrastado / a área sob ele.
Sensor
Forma de controlar: ponteiro ou teclado.
Activation constraint
Condição para começar (mover 4px).
Colisão
Regra que decide a área de destino.
DragOverlay
Cópia que segue o ponteiro, por cima de tudo.
Otimista / rollback
Muda antes da API; desfaz se ela recusar.
aria-live
Trecho cujas mudanças o leitor de tela anuncia.

Experimente

  1. Arraste com o mouse para "Feito"

    Esperado: a coluna sob o ponteiro fica índigo; ao soltar, título riscado; F5 mantém.

  2. Clique sem mover

    Esperado: abre a edição, não arrasta.

  3. Tab, Espaço, →, Espaço

    Esperado: o cartão anda uma coluna inteira.

  4. Pare a API e arraste

    Esperado: o cartão muda, volta e aparece "Não foi possível mover…". Suba a API de novo.

  5. Desfaça

    Exclua as tarefas de teste (clique → Excluir → Confirmar exclusão).

Teste seu entendimento

1. Torre, aviões, pistas e sombra?

DndContext, cartões (useDraggable), colunas (useDroppable) e DragOverlay.

2. Por que o id da coluna é o status?

over.id já diz o status de destino no onDragEnd.

3. Atualização otimista e seu risco?

Muda a tela antes da API; se ela recusar, rollback com aviso.

4. Por que pointerWithin + rectIntersection?

Ponteiro para o mouse; sobreposição quando não há ponteiro (teclado).

5. Por que o Enter fechava o diálogo?

O foco caía no X e o mesmo Enter o acionava; resolvido com preventDefault e foco no título.
