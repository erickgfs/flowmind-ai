Antes de começar

  • Aula 12 (React): componentes, estado e efeitos continuam iguais.
  • Servidor × navegador: o servidor entrega a página; o navegador a exibe e roda o JavaScript. localStorage e window só existem no navegador.

O problema e a ideia

O problema

React sozinho não é um site

  • Faltam rotas (/login, /dashboard), título por aba, fontes, build de produção.
  • Montar tudo à mão é trabalhoso e cheio de detalhes.

No Next.js, a pasta app/login/ com um page.tsx vira a rota /login. Ele pré-renderiza HTML para a página aparecer rápido.

Analogia

O shopping center

  • Rota = loja com endereço fixo (a pasta).
  • layout.tsx = corredor e vitrine em comum (a barra lateral).
  • page.tsx = o interior de cada loja.
  • Server Component = estoque nos fundos; Client Component = balcão de atendimento.
  • (app) = ala com segurança na porta, cujo nome não aparece no endereço.

Onde falha: o mesmo componente de cliente é pré-renderizado no servidor e depois "acorda" no navegador. Daí a fronteira use(browser()).

Por que use(browser()): o token só existe no navegador

O código, comentado

app/login/page.tsx · Server ComponentTSX
export const metadata: Metadata = { title: "Entrar" };

export default function LoginPage() {
  return (
    <Suspense fallback={<FullPageLoader />}>
      <AuthScreen />  {/* "use client" */}
    </Suspense>
  );
}
components/auth-gate.tsx · ClientTSX
"use client";
export function AuthGate({ children }) {
  use(browser("Sessão no localStorage."));
  const token = useAuthStore((s) => s.token);
  const router = useRouter();
  useEffect(() => {
    if (!token) router.replace("/login");
  }, [token, router]);
  return token ? children : <FullPageLoader />;
}

NEXT_PUBLIC_ é colado no build. NEXT_PUBLIC_API_URL vira texto dentro do JavaScript que qualquer visitante baixa. Só valores públicos; nada de segredos.

Glossário

App Router
Rotas do Next baseadas na pasta app/.
page.tsx / layout.tsx
Conteúdo de uma rota / moldura compartilhada.
(grupo)
Pasta que organiza rotas sem aparecer na URL.
Server Component
Padrão: roda no servidor, sem estado nem cliques.
Client Component
"use client": roda no navegador, com hooks e eventos.
Pré-renderizar
Gerar o HTML antes de alguém pedir (no build).
Hidratação
O React assume o HTML pré-renderizado e liga os cliques.
use(browser())
React 19.3: "esta parte só renderiza no navegador".
redirect()
Manda o visitante para outra rota.
NEXT_PUBLIC_
Variável embutida no JavaScript do navegador.
Cache Components
Next 16: dados dinâmicos por padrão; cache só com "use cache".

Experimente: uma rota protegida em 1 arquivo

  1. Crie src/app/(app)/sobre/page.tsx

    import type { Metadata } from "next";
export const metadata: Metadata = { title: "Sobre" };
export default function SobrePage() {
  return <p className="p-8">O FlowMind organiza tarefas.</p>;
}

  2. Abra http://localhost:3001/sobre

    Esperado: com a barra lateral (herdou o layout) e aba "Sobre · FlowMind"; sem "(app)" na URL.

  3. Saia e tente /sobre de novo

    Esperado: volta para /login: a guarda vale para a rota nova.

  4. npm run build

    Esperado: ○ /sobre na lista de rotas.

  5. Desfaça

    Apague src/app/(app)/sobre/; confira com git status.

Teste seu entendimento

1. layout, page e (app) no shopping?

Corredor em comum, interior da loja, ala com segurança que não aparece no endereço.

2. Server × Client Component?

Servidor: sem JavaScript no navegador, sem estado. Cliente: "use client", hooks e eventos.

3. Por que o AuthGate usa use(browser())?

O token está no localStorage; o servidor só pré-renderiza o fallback e a decisão acontece no navegador.

4. O AuthGate protege os dados?

Não; quem protege é a API (401 sem token válido).

5. Por que nada de segredo em NEXT_PUBLIC_?

Vai parar no JavaScript que qualquer visitante baixa.
