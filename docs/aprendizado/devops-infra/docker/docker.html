Antes de começar

Nenhuma aula anterior. Só três ideias que vamos usar o tempo todo:

  • Programa vs. processo: o programa é o arquivo instalado (o .exe). O processo é ele rodando. Abrir o Chrome duas vezes = 1 programa, 2 processos.
  • Terminal: janela onde você digita comandos em texto. No VS Code: Terminal → New Terminal.
  • Porta: o computador é um prédio, localhost é o endereço do prédio e a porta é o número do apartamento. PostgreSQL mora no 5432, Redis no 6379.

O problema e a ideia

O problema

"Na minha máquina funciona"

Instalar PostgreSQL e Redis direto no Windows funciona, mas cada pessoa precisa instalar as mesmas versões e configurar igual. Quem já tem a versão 14 de outro projeto entra em conflito com a 16. Desinstalar deixa sujeira.

O Docker roda cada programa numa caixa isolada, o container, que já vem com tudo que o programa precisa e não mexe no resto do PC.

Analogia

A receita e o bolo

  • Imagem = a receita. Fica guardada, não "roda".
  • Container = o bolo feito com a receita. É a coisa viva. Uma receita faz quantos bolos você quiser.
  • Docker Hub = o livro de receitas público da internet.
  • Jogar o bolo fora não apaga a receita.

Onde a analogia falha: bolo não "roda". O container é um programa em execução, que pode ser parado e ligado de novo sem ser destruído.

Glossário

Imagem
Pacote somente-leitura com um programa e tudo de que ele precisa. A receita.
Container
Uma imagem em execução: um processo isolado do resto do computador. O bolo.
Tag
A versão da imagem, depois dos dois-pontos. Em postgres:16-alpine, é 16-alpine.
Alpine
Linux mínimo, usado como base para deixar imagens pequenas.
Docker Hub
Site público com imagens prontas (hub.docker.com).
Docker Engine
O motor que fica ligado em segundo plano e realmente cria e roda os containers.
Docker CLI
O comando docker que você digita. Só leva pedidos ao Engine.
Docker Desktop
Aplicativo para Windows/Mac que instala e liga o Engine.
WSL2
Um Linux leve rodando dentro do Windows.
Kernel
O núcleo do sistema operacional, que controla memória, processos e hardware.
Volume
Pasta guardada pelo Docker fora do container, para os dados não sumirem.
Mapeamento de porta
-p 6380:6379: porta do Windows (esquerda) ligada à porta do container (direita).

Experimente você mesmo

  1. Rode seu primeiro container

    docker run hello-world

    Esperado: Hello from Docker! O Docker baixou a imagem, criou o container, o programa imprimiu a mensagem e terminou.

  2. Veja que ele ainda existe, parado

    docker ps -a

    Procure a imagem hello-world com status Exited (0): terminou, sem erro.

  3. Veja os containers do FlowMind

    docker ps

    Esperado: flowmind-postgres e flowmind-redis com Up ... (healthy).

  4. Entre num container e olhe em volta

    docker exec -it flowmind-redis sh
cat /etc/os-release   # "Alpine Linux": ele acha que é um Linux sozinho
ps                    # só os processos do próprio container
exit

  5. Desfaça o teste

    docker rm $(docker ps -aq --filter ancestor=hello-world)
docker rmi hello-world

Teste seu entendimento

1. Qual a diferença entre imagem e container?

A imagem é o pacote parado e somente-leitura (a receita). O container é a imagem em execução (o bolo). De uma imagem saem quantos containers você quiser.

2. Você rodou docker rm flowmind-postgres. A imagem sumiu?

Não. Só o container foi apagado. A imagem continua em docker images.

3. Por que o Docker no Windows precisa do WSL2?

Containers usam recursos do kernel Linux (namespaces e cgroups). O WSL2 fornece esse Linux dentro do Windows.

4. Em -p 5433:5432, em qual porta você conecta a partir do Windows?

Na 5433. A da esquerda é a do seu computador; a 5432 é a de dentro do container.
