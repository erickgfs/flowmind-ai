Antes de começar

  • Aula 6 (NestJS): controller, service, module e decorators.
  • Body: os dados que o cliente manda num POST ou PATCH, em JSON.
  • Status HTTP: 2xx deu certo, 4xx o cliente errou (400 dados inválidos, 401 sem login, 404 não encontrado, 409 conflito), 5xx a API quebrou.

O problema e a ideia

O problema

A internet manda de tudo

  • E-mail "abc", senha vazia, status: "FEITO", título de 2 milhões de caracteres.
  • Um campo userId acrescentado para criar tarefas em nome de outra pessoa.
  • Um if em cada rota é repetitivo e fácil de esquecer.

Um DTO descreve o formato esperado. O ValidationPipe confere todo body contra ele e responde 400 antes do controller rodar.

Analogia

O formulário do cartório

  • DTO = formulário oficial com os campos e as regras.
  • Decorators = instruções impressas ao lado de cada campo.
  • ValidationPipe = atendente da triagem: devolve na hora com a lista do que corrigir; recusa campo rabiscado fora do formulário.
  • Controller/service = escrivão: só recebe formulário conferido.

Onde a analogia falha: o atendente confere formato, não verdade. Ele não sabe se o e-mail já está cadastrado. Isso continua no service (409).

O que acontece com o body

As três opções do ValidationPipe

OpçãoBody enviadoO que acontece
sem opções{"title":"x","userId":"hack"}perigo userId chega ao controller
whitelist: true{"title":"x","userId":"hack"}descarta userId some em silêncio
+ forbidNonWhitelisted{"title":"x","userId":"hack"}recusa 400 property userId should not exist
transform: true{"email":" Ana@X.com "}converte chega ana@x.com, como instância do DTO

O código, comentado

src/main.tsTS
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,            // ignora extras...
    forbidNonWhitelisted: true, // ...e responde 400
    transform: true,            // instância + @Transform
  }),
);
src/auth/dto/register.dto.tsTS
export class RegisterDto {
  @Transform(({ value }) => value.trim().toLowerCase())
  @IsEmail({}, { message: 'email deve ser…' })
  email: string;

  @IsString()
  @MinLength(8)
  @MaxLength(72) // limite do bcrypt (aula 9)
  password: string;
}
src/tasks/dto/create-task.dto.tsTS
// sem userId: o dono vem do token JWT
export class CreateTaskDto {
  @IsString() @IsNotEmpty() @MaxLength(200)
  title: string;

  @IsOptional()          // pode faltar
  @IsEnum(TaskStatus)     // enum do Prisma
  status?: TaskStatus;

  @IsOptional() @IsDateString()
  dueDate?: string;      // "2026-12-31"
}
update-task.dto.ts · controllerTS
// mesmas regras, tudo opcional (PATCH)
export class UpdateTaskDto
  extends PartialType(CreateTaskDto) {}

// no controller, só declarar o tipo:
@Patch(':id')
update(
  @Param('id', ParseUUIDPipe) id: string,
  @Body() dto: UpdateTaskDto,
) { … }

Por que classe e não interface? Interfaces e import type somem quando o TypeScript vira JavaScript. O Nest lê o tipo do parâmetro em tempo de execução (graças ao emitDecoratorMetadata), então o DTO precisa ser uma class importada como valor.

Glossário

Body
Dados enviados com um POST/PATCH, geralmente em JSON.
Status HTTP
Número da resposta: 2xx ok, 4xx erro do cliente, 5xx erro da API.
DTO
Classe que descreve o formato exato dos dados que entram.
class-validator
Decorators de regra (@IsEmail) e a função que confere um objeto.
class-transformer
Transforma JSON numa instância da classe e roda os @Transform.
Pipe
Peça do Nest que valida ou converte uma entrada antes do controller.
whitelist
Descarta campos que não estão no DTO.
forbidNonWhitelisted
Responde 400 quando chegam campos desconhecidos.
transform
Entrega uma instância real do DTO e ativa os @Transform.
PartialType
Cria um DTO com as mesmas regras, mas tudo opcional.
Enum
Lista fechada de valores: TODO, IN_PROGRESS, DONE.
ISO 8601
Formato padrão de data em texto: 2026-12-31T18:00:00Z.
ParseUUIDPipe
Confere se um parâmetro da URL é um UUID; senão, 400.

Experimente você mesmo

  1. Suba a API e crie um usuário

    cd apps/api && npm run start:dev
curl -s -X POST localhost:3000/auth/register -H "Content-Type: application/json" \
  -d '{"email":"teste-dto@flowmind.dev","name":"Teste","password":"senha-forte-123"}'

    Esperado: 201 com um accessToken. Copie-o.

  2. Mande uma prioridade que não existe

    curl -s -X POST localhost:3000/tasks -H "Content-Type: application/json" \
  -H "Authorization: Bearer COLE_O_TOKEN" -d '{"title":"x","priority":"URGENTE"}'

    Esperado: 400 priority deve ser um de: LOW, MEDIUM, HIGH

  3. Aperte uma regra

    Em create-task.dto.ts, troque @MaxLength(200) por @MaxLength(10) e mande {"title":"um título bem comprido"}.

    Esperado: 400 title must be shorter than or equal to 10 characters

  4. Tente o campo proibido

    Mande {"title":"ok","userId":"qualquer"}.

    Esperado: 400 property userId should not exist

  5. Desfaça

    Volte o @MaxLength(200). No Prisma Studio (npm run prisma:studio), apague o usuário teste-dto@flowmind.dev; as tarefas vão junto.

Teste seu entendimento

1. No cartório, quem é o DTO e quem é o ValidationPipe?

O DTO é o formulário com as regras. O ValidationPipe é o atendente da triagem que devolve o formulário com a lista de erros antes do escrivão.

2. Qual a diferença entre whitelist e forbidNonWhitelisted?

whitelist descarta extras em silêncio; forbidNonWhitelisted responde 400 dizendo qual campo não deveria existir.

3. Por que o DTO é uma class e não uma interface?

Interfaces somem na compilação; o Nest precisa ler o tipo e os decorators em tempo de execução.

4. Por que o CreateTaskDto não tem userId?

O dono é quem está logado, e isso vem do token JWT. Aceitar userId no body permitiria criar tarefas em nome de outra pessoa.

5. Para que serve PartialType no PATCH?

Reaproveita todas as regras do CreateTaskDto, mas deixa os campos opcionais: o cliente manda só o que quer mudar.
