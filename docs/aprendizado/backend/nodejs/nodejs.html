O problema e a ideia

O problema

JavaScript fora do navegador?

  • A API precisa ficar ligada num servidor, mas JavaScript nasceu para rodar dentro do navegador.
  • Todo projeto usa bibliotecas de terceiros. Copiar arquivos na mão vira bagunça.
  • tarefa.titlo (erro de digitação) só explode quando o programa já está rodando.

Node.js executa o JavaScript, npm instala as bibliotecas e TypeScript confere os tipos antes de rodar.

Analogia

A cozinha profissional

  • Node.js é o fogão: sem ele a receita é só papel.
  • npm é o fornecedor. package.json é a lista de compras; package-lock.json é a nota fiscal com o lote exato.
  • node_modules é a despensa.
  • TypeScript é o chef revisor: "200 kg de sal? Deve ser 200 g".

Onde a analogia falha: ingredientes acabam; pacotes do npm não. Qualquer projeto baixa a mesma biblioteca quantas vezes quiser.

Glossário

Runtime
Programa que executa código de uma linguagem. O Node é um runtime de JavaScript.
Pacote
Código pronto de outra pessoa, que você instala e reutiliza.
npm / npx
Gerenciador de pacotes / executa o comando de um pacote sem instalá-lo globalmente.
package.json
Ficha do projeto: scripts e pacotes com a faixa de versões aceitas.
package-lock.json
Versões exatas instaladas, para todos instalarem igual.
node_modules
Pasta com os pacotes baixados. Nunca vai para o Git.
dependencies
Pacotes usados enquanto o programa roda.
devDependencies
Pacotes usados só no desenvolvimento (compilador, testes).
semver
MAIOR.MENOR.CORREÇÃO. Mudar o MAIOR pode quebrar código.
dist-tag / RC
Apelido de versão (latest) / versão "quase pronta", ainda em teste.
TypeScript
JavaScript com tipos verificados antes de rodar.
Compilar
Traduzir .ts para .js.
ESM
Sistema de import/export; imports locais terminam em .js.
Event loop
Mecanismo que deixa o Node atender outros pedidos enquanto um espera.
Monorepo
Um repositório com vários projetos dentro.
.env
Arquivo com variáveis de ambiente (senhas, portas). Fora do Git.

Teste seu entendimento

1. Qual a diferença entre package.json e package-lock.json?

O primeiro diz a faixa de versões aceita (^7.10.1); o lock registra a versão exata instalada.

2. Por que o Prisma CLI vai em devDependencies e o Client em dependencies?

O CLI só é usado no desenvolvimento; o Client é usado pela API enquanto ela roda.

3. O que o await faz com os outros pedidos?

Nada de ruim: enquanto um pedido espera o banco, o event loop atende os outros.

4. Por que fixamos prisma@7.10.1 em vez de @latest?

Porque latest apontava para uma RC 8.0.0 e ficaria diferente do @prisma/client 7.10.1.

5. Para que servem apps/ e packages/?

apps/ guarda os programas que rodam; packages/ guarda código compartilhado entre eles.
