O problema e a ideia

O problema

Por que não uma planilha?

  • Duas pessoas editam a mesma tarefa e uma alteração apaga a outra.
  • Achar uma tarefa entre um milhão precisa levar milissegundos.
  • O programa trava no meio do salvamento e o arquivo fica corrompido.
  • Alguém cria uma tarefa num projeto que não existe.

Um banco de dados resolve tudo isso. O PostgreSQL guarda os dados em tabelas, aplica as regras que você define e responde perguntas escritas em SQL.

Analogia

A biblioteca com bibliotecário

  • Os livros ficam no depósito (o disco). Você não entra lá.
  • Você pede ao bibliotecário (o servidor) numa língua que ele entende (o SQL).
  • Ele usa o índice para ir direto ao livro certo.
  • Ele aplica as regras da casa: nada de livro sem estante ou dois com o mesmo código.

Onde a analogia falha: o bibliotecário de verdade atende uma pessoa por vez. O PostgreSQL atende muitos clientes em paralelo.

Glossário

Banco de dados
Conjunto organizado de dados guardados de forma permanente.
SGBD
O programa que cuida do banco. O PostgreSQL é um SGBD.
Relacional
Guarda dados em tabelas que se relacionam entre si.
Tabela / linha / coluna
A "aba da planilha", cada item dela e cada atributo com tipo fixo.
Tipo de dado
integer (inteiro), text, boolean (sim/não), timestamp (data e hora).
NULL
"Sem valor". Diferente de zero ou de texto vazio.
Chave primária (PK)
Coluna que identifica cada linha de forma única, normalmente id.
Chave estrangeira (FK)
Coluna que aponta para a PK de outra tabela. Cria a relação.
SQL
A linguagem para criar tabelas e inserir, buscar, alterar e apagar dados.
psql
O cliente de terminal oficial do PostgreSQL.
Transação
Grupo de comandos que acontece por inteiro ou não acontece.
Índice
Estrutura que acelera buscas, como o índice remissivo de um livro.
JSONB
Coluna que guarda dados flexíveis (JSON) de forma pesquisável.
pgvector
Extensão que permite buscar textos pelo significado, usada com IA.

SQL comentado

CRUD: criar, ler, alterar, apagarSQL
CREATE TABLE tarefas (
  id        serial PRIMARY KEY,       -- número automático e único
  titulo    text NOT NULL,            -- obrigatório
  status    text DEFAULT 'pendente',  -- valor padrão
  criada_em timestamp DEFAULT now()   -- agora
);

INSERT INTO tarefas (titulo)
  VALUES ('Configurar Docker');

SELECT * FROM tarefas;            -- tudo
SELECT titulo FROM tarefas
  WHERE status = 'pendente';      -- filtrado

UPDATE tarefas SET status = 'feita'
  WHERE id = 1;                  -- SEMPRE com WHERE

DELETE FROM tarefas
  WHERE id = 1;                  -- SEMPRE com WHERE
relações e transaçãoSQL
-- JOIN: juntar duas tabelas pela FK
SELECT t.titulo, p.nome AS projeto
  FROM tarefas t
  JOIN projetos p ON p.id = t.projeto_id;

-- Transação: tudo ou nada
BEGIN;                             -- abre
UPDATE tarefas SET projeto_id = 2
  WHERE projeto_id = 1;
DELETE FROM projetos WHERE id = 1;
COMMIT;                            -- confirma as duas
-- se algo falhar antes do COMMIT,
-- ROLLBACK desfaz tudo

Experimente você mesmo

Uma tabela de teste, criada e apagada no fim. Nada aqui afeta o projeto.

  1. Entre no banco

    docker exec -it flowmind-postgres psql -U flowmind -d flowmind

    Esperado: o prompt vira flowmind=#.

  2. Confirme que não há tabelas

    \dt

    Esperado: Did not find any relations.

  3. Crie a tabela e insira três tarefas

    CREATE TABLE tarefas_teste (
  id serial PRIMARY KEY,
  titulo text NOT NULL,
  status text DEFAULT 'pendente'
);
INSERT INTO tarefas_teste (titulo) VALUES
  ('Subir o PostgreSQL'), ('Subir o Redis'), ('Criar a API');

    Esperado: CREATE TABLE e INSERT 0 3.

  4. Busque, filtre e altere

    SELECT * FROM tarefas_teste;
UPDATE tarefas_teste SET status = 'feita' WHERE id IN (1, 2);
SELECT titulo, status FROM tarefas_teste WHERE status = 'pendente';

    Esperado no último: só Criar a API | pendente.

  5. Veja uma regra funcionando

    INSERT INTO tarefas_teste (status) VALUES ('feita');

    Esperado: erro violates not-null constraint. O banco recusou uma tarefa sem título.

  6. Desfaça e saia

    DROP TABLE tarefas_teste;
\q

Teste seu entendimento

1. Qual a diferença entre chave primária e chave estrangeira?

A primária identifica cada linha da própria tabela (o id da tarefa). A estrangeira aponta para a primária de outra tabela (projeto_id aponta para projetos.id).

2. O que faz DELETE FROM tarefas; ?

Apaga todas as tarefas, porque não há WHERE para filtrar.

3. Por que usar uma transação ao mover várias tarefas?

Para garantir "tudo ou nada": se algo falhar no meio, nenhuma tarefa é movida.

4. No FlowMind, quem é o servidor e quem é o cliente?

O servidor é o PostgreSQL no container flowmind-postgres. Os clientes são o psql e, a partir da Fase 2, a API.

Evolução prática · Fase 2

As primeiras tabelas reais: UUID, ENUM e ON DELETE CASCADE

Na Fase 2 o Prisma (aula 7) criou as tabelas de verdade. Os nomes finais ficaram em inglês e no plural: users e tasks. A tabela projetos do exemplo ainda não existe; por enquanto cada tarefa pertence direto a um usuário.

Por que UUID em vez de serial para o id?

Com serial os ids são 1, 2, 3... e qualquer um adivinha o próximo. O UUID é aleatório: não revela quantos registros existem nem facilita adivinhar ids alheios.
