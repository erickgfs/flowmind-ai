Redis, do zero

Uma memória super-rápida ao lado do PostgreSQL, para guardar respostas prontas por alguns segundos, contar acessos e enfileirar trabalhos de IA.

Antes de começar

Leia antes as aulas 1 (Docker) e 2 (PostgreSQL). E uma ideia nova: o computador guarda coisas em dois lugares.

Memória RAM

1 segundo

Extremamente rápida, mas pequena. Esquece tudo quando desliga.

Disco (SSD)

vários minutos

Grande e permanente, mas bem mais lento. É onde o PostgreSQL guarda as tabelas.

Escala imaginária: se ler um dado da RAM levasse 1 segundo, ler do SSD levaria vários minutos. A diferença real é de centenas a milhares de vezes.

O problema e a ideia

O problema

O mesmo trabalho, 500 vezes

Se 500 pessoas abrem o mesmo quadro de tarefas no mesmo minuto, o PostgreSQL calcula a mesma resposta 500 vezes. O mesmo vale para a sessão de login (checada a cada clique), para contar chamadas à IA e para trabalhos demorados que deveriam esperar numa fila.

O Redis guarda dados na RAM, no formato chave → valor, e responde em microssegundos. Usamos ele como cache: um lugar para respostas prontas por um tempo.

Analogia

A bancada e a despensa

  • A despensa é o PostgreSQL: cabe tudo, é permanente, mas buscar demora.
  • A bancada é o Redis: pequena, mas tudo está à mão.
  • Você olha primeiro na bancada. Se não tem, busca na despensa e deixa uma porção na bancada.
  • Na bancada tudo tem prazo de validade: o TTL.

Onde a analogia falha: nossa bancada tem um diário (AOF) e não perde tudo ao reiniciar. Mesmo assim, a fonte oficial dos dados continua sendo o PostgreSQL.

Cache-aside: olhar na bancada primeiro

Um comando por vez. O Redis executa os comandos numa fila única. Como tudo está na RAM, cada um leva microssegundos. A vantagem: INCR (somar 1) é atômico. Mil pessoas somando ao mesmo tempo nunca perdem uma contagem. É assim que se faz um limite de "20 chamadas à IA por minuto".

Persistência. O AOF grava cada escrita num diário em disco; ao reiniciar, o Redis relê o diário. O RDB tira uma "foto" de tempos em tempos e perde o que mudou depois dela. No FlowMind usamos AOF, guardado no volume redis_data.

Glossário

Chave → valor
O dado é guardado sob um nome (a chave) e achado por ele.
Cache
Cópia temporária de uma resposta, num lugar rápido, para reuso.
Hit / miss
Hit: a resposta estava no cache. Miss: não estava, busca na fonte.
TTL
"Time To Live": segundos até a chave expirar e sumir sozinha.
Invalidar
Apagar uma chave do cache porque o dado original mudou.
Sessão
Registro de que um usuário está logado.
Fila
Lista de trabalhos esperando, processados em ordem de chegada.
Atômico
Acontece inteiro, sem ninguém interromper no meio.
AOF / RDB
Diário de comandos / foto periódica: as duas formas de salvar em disco.
redis-cli
O cliente de terminal do Redis.

Comandos comentados

entrar no Redisterminal
# troque SENHA pelo REDIS_PASSWORD do .env
docker exec -it flowmind-redis \
  redis-cli -a SENHA --no-auth-warning
#  redis-cli           cliente do Redis
#  -a SENHA            autentica
#  --no-auth-warning   esconde o aviso de
#                      senha na linha de comando

PING                    # → PONG
INFO server             # versão e detalhes
SCAN 0 MATCH cache:*    # procura chaves sem travar
dentro do redis-clio essencial
SET nome "FlowMind"          # guarda
GET nome                     # → "FlowMind"
SET cache:x "abc" EX 60      # guarda por 60s
TTL cache:x                  # segundos restantes
                             # -1 sem prazo · -2 não existe
EXPIRE nome 30               # dá prazo a quem já existe
DEL nome                     # apaga
INCR visitas                 # +1, atômico
HSET tarefa:1 titulo "API"  # hash com campos
HGETALL tarefa:1
LPUSH fila:ia "doc-7"        # entra na fila
RPOP fila:ia                 # sai o mais antigo

Experimente você mesmo

  1. Entre no Redis

    docker exec -it flowmind-redis redis-cli -a SENHA --no-auth-warning
PING

    Esperado: PONG.

  2. Guarde e leia

    SET aula:saudacao "ola, redis"
GET aula:saudacao

    Esperado: OK e depois "ola, redis".

  3. Veja uma chave expirar

    SET aula:temporaria "some em 15s" EX 15
TTL aula:temporaria

    Rode TTL algumas vezes: o número cai. Depois de 15s, GET aula:temporaria responde (nil).

  4. Conte de forma atômica

    INCR aula:contador
INCR aula:contador
INCR aula:contador

    Esperado: 1, 2, 3.

  5. Simule uma fila

    LPUSH aula:fila "resumir doc 1" "resumir doc 2"
RPOP aula:fila

    Esperado: "resumir doc 1". O primeiro a entrar é o primeiro a sair.

  6. Desfaça e saia

    DEL aula:saudacao aula:contador aula:fila
exit

Teste seu entendimento

1. Por que o Redis é tão mais rápido para ler uma chave?

Porque os dados estão na RAM e a busca é direta pela chave. O PostgreSQL trabalha com disco e consultas mais complexas.

2. O que a API faz num cache miss?

Busca no PostgreSQL, guarda uma cópia no Redis com TTL e responde.

3. Para que serve o TTL?

Para a chave sumir sozinha. Evita encher a memória e limita por quanto tempo um dado velho pode aparecer.

4. Se o container do Redis reiniciar, as chaves somem?

No FlowMind, não: o AOF está ligado e fica no volume redis_data. Ao reiniciar, o Redis relê o diário.
